# 07 — Дорожная карта

Каркас этапов развития системы. Без дат и без экономики (D5): порядок и
содержание, а не сроки. Каждый этап заканчивается проверяемым результатом.

| # | Этап | Что делаем | Результат | Человек делает |
|---|---|---|---|---|
| 0 | **База знаний** | Опыт ADAPT собран, обобщён, вынесен в отдельный проект | этот репозиторий | — |
| 1 | **Прототип для руководства** | Презентация / демо пути тикета | артефакт + согласие на этап 2 | презентует |
| 2 | **Обобщённый фреймворк на знакомом проекте** | Ставим `framework/` в ADAPT вместо старых команд, пишем `PROJECT-PROFILE.md` для ADAPT, гоняем ручной цикл на новых шаблонах; добавляем тестировщика и чистильщика как отдельные запуски | фреймворк работает на реальном тикете без ADAPT-специфики в шаблонах | запускает этапы вручную, как сейчас |
| 3 | **Конвейер внутри одного запуска** | Диспетчер сам передаёт тикет между агентами: драфт → ревью спеки → реализация → ревью кода и чистка → тест → PR; эскалация вопросом | один запуск на тикет вместо пяти | запускает конвейер, отвечает на эскалации, принимает PR |
| 4 | **Интеграция с трекером** | Чтение тикета, смена статусов, комментарии, ссылка на PR, передача в QA при закрытой среде | ход тикета виден в Jira без чтения чатов | смотрит Jira, принимает PR |
| 5 | **Самостоятельный выбор тикетов** | Диспетчер сам берёт тикеты из пула (спринт, «К работе», назначены на разработчика), решает очередность и параллельность в пределах потолка (D28, D32, D33) | тикеты уходят в работу без ручной постановки в очередь | назначает тикеты, запускает диспетчера, отвечает на эскалации, принимает PR |
| 6 | **Знакомство с проектом** | Агент-аналитик собирает профиль нового проекта из репозитория, документации и QA-сессии | профиль за одну сессию на проекте другого стека | отвечает на вопросы аналитика |
| 7 | **Второй проект — проверка независимости от стека** | Пилот на проекте с другим стеком и доменом | конвейер прошёл тикеты без правки фреймворка (или список того, что пришлось вынести в профиль) | ведёт пилот |
| 8 | **Масштабирование** | Шаблон внедрения для команд, метрики качества конвейера, экономика | процесс подключения нового проекта | решает, какие проекты подключать |
| 9 | **BA/PM-часть** | Декомпозиция эпиков, проверка плана эпика (`verify-epic-plan`), подготовка тикетов из PM/BA-документации | конвейер начинается с эпика, а не с тикета | ставит цели эпика |

Порядок этапов 4–6 гибкий: 6 можно поднять раньше, если пилот на втором
проекте (7) нужен быстро.
