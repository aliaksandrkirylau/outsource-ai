# Workshop prep - before a client session, workshop or internal review

From the Spec Framework's workshop-prep, over this KB.

1. Ask the goal if it is not clear: discovery, requirements review, architecture session, issue
   resolution, progress.
2. Read: the open Questions and change request candidates (`index.md`), proposed notes that wait
   for the client, the stable Decisions (so nothing decided gets asked again), the Requirements and
   Concerns in the session's area, and the matching question bank in `reference/` for gaps.
3. Write `<date> <session> - prep.md` in the person's role folder (`pm/` or `ba/`):
   - Status brief: one paragraph on where this area stands.
   - Questions, grouped by topic rather than priority. One thing per question, a line of context,
     options where the answer is likely one of a few. Mark as must-have the ones that block a WBS
     line. 15-25 for a session at most; if questions go to the client in advance, send the top 5-7.
   - Agenda: time-boxed, with the must-have outcomes (the session fails without them) and the
     nice-to-haves.
   - To confirm: proposed notes that need the client's yes, each with its ID for us and plain
     wording for them.
4. Never re-ask what a stable Decision already answers. After the session, ingest it.
