Page 2 - Calculations, Server Access & API Scope

As for the desktop application, at this stage it is assumed that all calculation and modeling logic
resides within the app code, and using a central server for these calculations is not required.
However, if in the future you decide to make the formulas flexible or allow different rate values via
the Admin panel of the web application, the lack of connection to a central server may cause issues,
as the calculations would no longer work offline in that scenario (note - calculations will be
hardcoded based on algorithms and formulas you shared at the current version of the solution).

In general, if any data from the central server is required for calculating/modeling and we can't
store this data in a desktop app with periodic updates/sync for some reason (for example parameters
should be instantly up to date with central server, or calculation needs online data from other job
sites for evaluation), it will require evaluation of such calculations on central server.

One more point regarding the offline mode limitation: since the reporting module exists in both the
web and desktop applications, if the desktop application loses connection to the central server, any
reports generated by the user on the web app side will be based on the last synchronized data. The
data will only be updated once the connection is restored.

We made a lot of concessions to stay in the budget that you requested. From a technical perspective,
implementing it is certainly feasible. However, in order to provide an accurate estimate of additional
effort required, we would need to clarify the number of endpoints, the types of requests, and the
complexity of those requests.

If API development is required, we can address it during the discovery stage and provide a separate
scope estimation based on the specific requirements.

1. Responsive design for a web application is an approach to interface design in which the
   application adapts correctly to different screen sizes (desktop, tablet, smartphone), maintaining
   usability and functionality to ensure a comfortable user experience on any device.

   The default desktop frame is 1440x1024 pixels

   Regarding the limitations or exclusions resulting from this assumption, The designer will not create
   layouts for screen behavior on devices with resolutions below 1440×1024 (tablets and mobile phones).
   As a result, the implementation on such devices may appear "stretched" or include gray areas on some
   screens, while on others content may be cropped or require excessive scrolling.

   If adaptive design is required, we can discuss it during the discovery stage and provide a separate
   effort estimation based on the requirements.
