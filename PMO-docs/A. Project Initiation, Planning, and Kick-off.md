# A. Project Initiation, Planning, and Kick-off

The A-block covers the full project start path: from receiving the project opportunity / pre-sale handover to formal client kick-off.

This block is divided into two logical parts:

## A01-A09. Project Initiation, Baseline Validation, and Start Decision

### Main PM responsibility

The PM converts the pre-sale opportunity into a validated delivery baseline and helps the company make a controlled decision whether the project should move forward.

At this stage, the PM does not simply accept the project as already ready for delivery. The PM collects project context, identifies key actors and ownership, validates sold scope and estimates, checks assumptions and risks, prepares roadmap and preliminary resource model, calculates initial project economy, and validates the baseline with internal and external stakeholders.

The main outcome of A01-A09 is a clear answer:

- what problem the project solves;
- what value the project brings;
- what the company has formally committed to in the signed contract;
- what scope and critical delivery areas are expected;
- whether estimates, assumptions, delivery approach, resources, timeline, and economy are realistic enough;
- what risks, blockers, dependencies, and clarification gaps exist;
- whether internal stakeholders approve the project to move forward;
- whether the client-facing delivery baseline is confirmed or still requires clarification.

### Steps included

| **Step** | **Purpose** |
| --- | --- |
| A01. Receive pre-sale handover and onboard to the project context | Collect pre-sale materials and understand the opportunity context. |
| A02. Define External/Internal Stakeholders, Key project actors, and set up internal communication | Identify who is involved, who owns what, and where internal coordination happens. |
| A03. Review final contract and confirm contractual baseline | Confirm which contract version is the baseline and what the company has formally committed to deliver, report, and support. |
| A04. Describe the project and define the project context | Define client problem, goals, expected outcomes, assumptions, constraints, and value context. |
| A05. Validate pre-sale scope, WBS estimates, assumptions, and delivery approach | Check whether sold scope, estimates, role assumptions, and delivery approach are realistic. |
| A06. Identify initial risks, dependencies, blockers, and change gaps | Convert initiation concerns into controlled risks, issues, dependencies, and clarification gaps. |
| A07. Create initial project roadmap and milestone schedule | Build the first delivery timeline and preliminary resource model. |
| A08. Calculate and validate initial project economy | Check whether the planned delivery setup is economically acceptable. |
| A09. Validate project baseline with internal and external stakeholders | Confirm whether the project can move forward and document the business / strategic rationale and client baseline confirmation. |

## A10-A14. Project Setup, Team Alignment, and Client Kick-off

### Main PM responsibility

The PM converts the validated baseline into a ready-to-start delivery setup.

At this stage, the project has already passed the baseline validation gate. The PM now needs to form the project team, confirm that the team can work within the baseline, prepare the project management system, align the team internally, prepare the client kick-off, and formally start the project with documented agreements.

The main outcome of A10-A14 is a project that is ready for active delivery:

- team composition is confirmed;
- resource plan and P&L are updated with confirmed people;
- project management system is set up;
- team understands how the project will work;
- team has reviewed baseline feasibility;
- kick-off agenda and client-facing process topics are prepared;
- client kick-off is conducted;
- start agreements, open questions, responsibilities, and next steps are documented.

### Steps included

| **Step** | **Purpose** |
| --- | --- |
| A10. Run staffing process and approve project team composition | Run formal staffing, review proposed candidates, approve team fit, and update Resource Plan / P&L. |
| A11. Set up the minimal required project management system | Prepare Jira / tracker, documentation structure, sensitive storage, PROREP, knowledge container, onboarding rules, Communication Plan draft, and required project links. |
| A12. Align project team on project start | Align the confirmed team on project context, working model, Communication Plan draft, delivery assumptions, and baseline feasibility. |
| A13. Prepare for client kick-off | Prepare kick-off agenda, materials, client-facing process topics, questions, and required client inputs. |
| A14. Kick off project | Conduct client kick-off, align start expectations, document agreements, and update project artifacts where needed. |

## Management logic of the A-block

A01-A09 answer: **Should and how can this project move forward?**

A10-A14 answer: **Are we ready to start delivery with the confirmed team and documented client agreements?**

The key transition point is A09. After A09, the project baseline is approved or accepted with constraints, and the PM can move from validation to setup.

A14 closes the A-block. After A14, the project moves from initiation and setup into regular project execution cycles.

It is appropriate to change the order of steps based on project needs, and several steps can be performed in parallel.
